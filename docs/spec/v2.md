# Komodo V2: the assembly line, not the factory

Komodo is a set of rules, roles, standards, skills, and guardrails that any agent host renders and runs. The host is the factory; Komodo is the line. Moving to another host is one adapter file and one `komodo install --host` call. Nothing in the repo knows which host is running.

Status: proposal, 2026-09-21. Replaces the V1 orchestrator. The decisions this reverses are noted in the last section.

## Use cases

| # | Use case | V2 answer |
|---|---|---|
| 1 | Agentic loop over `BACKLOG.md`, rapid iterations, CI-like stages | The `run` skill is the line; `komodo tasks` is the deterministic parser; roles are the stations |
| 2 | Ad hoc sessions with Komodo context and standards | `komodo install` renders rules, standards, and roles for every session on the host |
| 3 | Ollama and local models by default, hybrid then fully local | Profiles map tiers to providers; Codex with `--oss` is the fully local host today |
| 4 | One config across Claude, GPT, Ollama, and beyond | Source is three neutral formats; one adapter per host |
| 5 | One context and standards set for every Komodo dev and repo | Install is per machine, a repo carries only `AGENTS.md` and `BACKLOG.md` |
| 6 | Lightweight hardened guardrails | One guard script, one policy file, one test table, both hosts |

## Principles

1. **Source is neutral.** `AGENTS.md`, `SKILL.md`, and a role file with frontmatter. Both Claude Code and Codex read the first two natively; a role renders to an agent definition in about 40 lines.
2. **Judgment in the agent, mechanics in Python.** Parsing the backlog, picking the ready set, rewriting a status, checking a comment, denying a command: stdlib Python. Reading a diff, building, reviewing: the agent.
3. **The guard is the only enforcement point.** Host permission lists are a convenience layer. The git and destruction policy holds with hooks alone, because on some hosts that is all there is.
4. **Nothing host-specific outside `adapters/`.** A skill or role never names a host tool, a host path, or a host flag. `komodo doctor` lints for it.
5. **No repo config.** Defaults in `komodo/config.py`, a per-machine overlay in `~/.komodo/config.json`. A repo carries `AGENTS.md` and `BACKLOG.md`, nothing else.
6. **Always-on context under 1500 tokens.** Rules only. Standards load by extension trigger. Roles load when spawned.

## Layout

```
komodo/
  AGENTS.md                  universal rules, always on, both hosts read it
  rules/
    accessibility.md         human-facing output contract, rendered into AGENTS.md
    backlog.md               the grammar `komodo tasks` parses
  roles/<role>.md            frontmatter: tier, tools, session; body: the brief template
  skills/
    run/SKILL.md             the assembly line
    review/SKILL.md          cold review of a diff
    backlog/SKILL.md         write and refine tasks in the grammar
    standards-<x>/SKILL.md   one per language or domain, trigger by extension
  policy.json                protected refs, forbidden verbs, destructive patterns, prod markers
  hooks/
    guard.py                 PreToolUse on shell, edit, write; reads policy.json and the task scope
    inject.py                SessionStart; prints the repo work state
  adapters/
    claude.py                renders ~/.claude: CLAUDE.md include, agents, skills, hooks, settings
    codex.py                 renders ~/.codex and ~/.agents: AGENTS.md, agents/*.toml, skills, hooks.json, config.toml
  config.py                  profiles: tier -> provider, model, effort per host
  tasks.py                   parse, lint, next, done
  comments.py                the comment lint
  doctor.py                  references, portability, drift
  bridge.py                  stdio MCP server over Ollama, standard library, spawned by the host
  cli.py                     install | doctor | tasks | comments | run | bridge
tests/
scripts/verify.py
templates/project/           AGENTS.md, BACKLOG.md, CHANGELOG.md for a new repo
```

Target size: about 900 lines of Python. V1 is 4933 plus 1013 of Go.

## The assembly line

Each station is one step in `skills/run/SKILL.md`. The skill stays under 1500 tokens; anything mechanical is a `komodo tasks` call so the session never re-reads loop text after compaction.

| Station | Who | What |
|---|---|---|
| Intake | `komodo tasks next --json` | The next READY group, its tasks, dependencies, waves by directory, and context paths |
| Context | scout role | Collects `files` and `context` into a brief, clipped to the profile's byte cap |
| Definition | planner role, only for REFINEMENT | Writes tasks in the grammar; `komodo tasks lint` gates promotion |
| Injection | the skill | Fills the builder's brief template: task block, context excerpts, standards by extension |
| Build | builder role, one per task, in a worktree | Scoped to `files`; the guard denies writes outside the scope |
| Enforce | `done_when`, `komodo comments check`, the repo's verify | Mechanical, before any review |
| Review | reviewer role, fresh context | Reads the diff only, never the builder transcript, on a different tier or provider when the profile says so. One pass per group, one repair pass |
| Publish | the skill, under the guard | Commit on `<type>/<name>`, push, PR, status to DONE via `komodo tasks done` |
| Report | the skill | The accessibility summary, nothing else |

Waves: tasks in disjoint directories run at once, each in its own `git worktree add`. The skill merges worktrees back in wave order and stops on a conflict; it never resolves one.

Headless: `komodo run <group>` is a launcher of about 30 lines. It scrubs push credentials from the environment, picks the host from the profile, and runs `claude -p "/run <group>"` or `codex exec "$run <group>"` with the role's output schema. It exits with the host's exit code.

### Why a skill loop again

The 0.x loop failed for measured reasons: nine phase gates, three to four reviewer forks per band, a full verify on every Stop, and 7k tokens of loop text re-read after every compaction. V2 keeps every V1 fix that removed those costs and moves the rest into the host:

- **One review pass per group** and one repair pass, as in V1.
- **Mechanics are commands**, not prose. The skill's text is under 1500 tokens and is a list of commands to run and roles to spawn.
- **Worktrees, parallel agents, and background agents are host features now.** In 0.x every fork was cold and serial.
- **Verify runs once per wave**, from `done_when`, not on every Stop.

The check: TG-03.4 runs the same group under V1 and V2 and records wall time and tokens in the PR. If V2 is slower by more than a wave, the skill is wrong, not the design.

## Roles

A role file is the brief. Frontmatter declares what the adapter needs; the body is the template the skill fills.

```markdown
---
name: builder
tier: standard          # light | standard | heavy; a profile maps it
tools: [read, edit, write, shell, search]
session: true           # also rendered as a session agent
returns: builder.schema.json
---
You are a builder. You own exactly the files listed under Scope. ...
## Task
{{task}}
## Scope
{{files}}
## Context
{{context}}
## Standards
{{standards}}
```

Tool names are Komodo's five verbs; the adapter maps them to the host's tool names.

## Profiles and local models

A profile maps each tier to a provider, a model, and an effort, per host. The role never names a model.

| Profile | Host | light | standard | heavy | reviewer |
|---|---|---|---|---|---|
| `claude` (default) | Claude Code | haiku | sonnet | opus | opus |
| `codex` | Codex | gpt-5-codex-mini | gpt-5-codex | gpt-5-codex | gpt-5-codex |
| `local` | Codex `--oss` | qwen3:1.7b | qwen3-coder | qwen3-coder | qwen3-coder |
| `hybrid` | Claude Code | ollama via bridge | sonnet | opus | opus, or ollama |

Model names in this table are placeholders the config verifies at install time; the role and skill files never carry them.

On Claude Code a subagent cannot run on Ollama. A light role in the `hybrid` profile calls the bridge from its body instead: `komodo bridge` is a stdio MCP server in the standard library that the host spawns, so there is no process to keep alive and nothing to install beyond Ollama. The reviewer tier may also point at Ollama, so a review never shares a vendor with the build. On Codex the `local` profile sets `oss_provider = "ollama"` and every tier runs locally. Fully local means Codex or a future open host; the source does not change.

An unbiased review is a profile choice: the reviewer tier may point at a different provider than the builder tier.

## The non-proprietary day

Both Komodo devs run Claude Code today. The plan assumes a day when the host is something Anthropic does not own, and it is built so that day costs one adapter file:

- **Nothing outside `adapters/` names a vendor, a host tool, a host path, or a host flag.** `komodo doctor` fails on a leak.
- **The three source formats are open.** `AGENTS.md` and `SKILL.md` are read natively by Codex, OpenCode, and others; a role renders to any of them.
- **Codex is the rehearsal, not the destination.** Its CLI is open source and its surfaces match Claude Code one for one, so it proves the source is neutral with the least work. OpenCode, Goose, or whatever wins later is a third adapter under the same source.
- **The exit test:** `komodo install --host <new>` with zero changes outside `adapters/`, then one group through the launcher. TG-03.6 runs that test once, under Codex.
- **Subscriptions do not travel.** Since April 2026 a Claude subscription covers only Anthropic's own apps. Any other host bills an API or runs locally; the `local` profile is the answer that costs nothing.

## Guardrails

One script, the guard, on every host's PreToolUse for shell, edit, and write. It reads `policy.json` and, in a worktree, the task scope the skill wrote to `.komodo/scope.json`.

Denied:
- **Git**: push, commit, merge, or delete on a protected ref; force; amend; rebase; reset; checkout; restore; any co-author or generated-by trailer.
- **Destruction**: `rm -rf` outside the worktree, `DROP DATABASE`, `TRUNCATE`, `terraform destroy`, `kubectl delete namespace`, cloud delete verbs, and any command naming a host in `policy.json` prod markers.
- **Scope**: an edit or write outside the task's `files` when a scope file exists.

Behaviour: deny only on a finding. An internal error is logged to stderr and allowed, because a guard that fails closed stalls every command on one bug. The cost of fail-open is bounded by a test table of at least 60 commands in the guard test table that verify runs.

Credentials: the headless launcher strips push tokens, credential helpers, and SSH identities. In an interactive session the guard is the gate, and a dev's own terminal is the dev's own.

## Distribution

Every Komodo dev clones this repo and runs one command:

```
python3 -m komodo install --host claude    # or --host codex, or both
```

Install renders into the home directory only. `komodo doctor` reports drift between the rendered layout and the source, and a broken reference in any rule, role, or skill. A repo starts from `templates/project/`.
